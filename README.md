# 東石保險服務平台

保險業務員的工作平台：理賠／契變文件下載、人壽客戶與保單管理、產險管理、保單知識庫、保障健診報告，以及每天早上的財經日報推播。

- 網站：GitHub Pages（本 repo `eastonesd/eastone.com`，推到 `main` 就上線，約 1～2 分鐘生效）
- 資料庫與後端：Supabase 專案 `kocyedkngpxckixtudku`
- 品牌：網站名稱為「東石保險服務平台」；**財經日報等對外推播的署名維持「東石系統」**（避開保險業務員管理規則第 16、19 條），不要改回。

## 二、人壽管理（`clients/`）

### 客戶資料
- 每位客戶一張資料卡，「姓名」欄稱為**被保險人**。
- 資料卡按鈕：新增／修改保單、編輯資料、保單健診報告。
- 右上角頭像選單：Email、LINE 提醒、修改密碼、保單知識庫、聯絡我們、登出。
- 日期可切換**西元／民國**，民國可直接打 `1151107`；資料庫一律存西元。

### 新增／修改保單（`policy.html`）
- 一頁完成：保單號碼（10 碼－2 碼）、折扣（預設 1%）、要保人／被保人／繳費人、主約、附約、保單狀況、繳費管道、受益人、服務人員。
- **保單歸在被保險人的資料卡**：被保人選了另一位客戶時，儲存後自動存到被保人的卡上（原卡的舊筆會移除），並跳到那張卡繼續編輯。
- **主約**：先打險種代號（例 `IAT`），再選版本，預設最新版；帶出險種名稱、主要／次要類別，知識庫有建檔的商品還能「試算」保費。
- **附約**：用關鍵字、中文名稱或險種代號查詢後勾選加入。
- **邊打邊建檔**：主約或附約代號不在保單資料庫時，照填險種名稱與類別，**儲存保單時自動建進保單資料庫**，並標記「自動建立」。目前 dkyp2377 與 tpbu 都可使用。
- **點選面板**：類別、繳費年期、保障期間點一下就跳出全部選項（東石深藍＋金配色，`picker.js`／`picker.css`），沒有的值也能直接打字。
- **豁免附約**：繳費年期與保障期間固定為「同主約繳費期滿日」；健診時自動換算成「主約繳費期滿日 − 豁免生效日」。
- 信用卡卡號每 4 碼自動空格、存檔只存數字；有效期限為 MM / YY。

### 繳費年期選項

| 種類 | 選項 |
|---|---|
| 主約 | 10年、15年、20年、30年 |
| 壽險類主約* | 躉繳、2年、3年、6年、7年、8年、10年、15年、20年 |
| 附約 | 1年、10年、65歲、74歲、75歲、84歲、90歲、95歲 |

\* 主要或次要類別是：壽險、增額壽險、還本壽險、養老保險、房貸壽險、小額終老、分紅、利變、利變年金、利變即期年金。

### 保單資料庫（原「保單代號維護」）
- 資料表 `insurance_codes`：`code`（險種代號）、`name`（險種名稱）、`kind`（`main` 主約／`rider` 附約）、`cat1`／`cat2`（主要／次要類別）、`auto_created`（登打保單時自動建立）。全公司共用。
- 同一險種的各版本收成一列，點一下展開／收合。版本規則：代號最後一碼是數字、前一碼是英文才算同險種（IAT／IAT1／IAT2 → IAT；PF55 這類不算）。
- 新增時可填主要／次要類別；也接受「主要/次要」寫法（例 `意外/身故與失能`）或舊寫法（例 `利變增額` 會自動拆成 利變／增額壽險）。規則在 `clients/db.js` 的 `CAT_SPLIT_RULES`、`CAT_ALIASES`。

### 險種類別（主約、附約各一套，主要／次要都從同一套選）

| 種類 | 類別 |
|---|---|
| 主約 | 壽險、增額壽險、還本壽險、養老保險、房貸壽險、小額終老、分紅、利變、利變年金、利變即期年金、意外、防癌、還本醫療、實支醫療、定額醫療、長照、失智、失能、重大傷病、重大疾病、特定傷病、投資U、投資V、還本、終身、定期、國際、甲型、乙型 |
| 附約 | 意外、身故與失能、防癌、定額、實支實付、住院醫療、自負額、豁免、骨折、手術、一次金、長照、定期 |

舊名稱會自動換成新名稱：重傷→重大傷病、重疾→重大疾病、特傷→特定傷病、意外險→意外、小額終老保險→小額終老；附約的傷害→意外、死殘→身故與失能、日額→定額。

### 保單健診
- `checkup.html`：以被保人為單位，跨客戶彙整保障、時間軸、保費、條款提醒；保障與理財分開。
- `report.html`：「保障內容健診報告」12 頁 A4 PDF（封面、保單目錄、保費配置、理財、保障視圖、人生責任、醫療、保障年齡時間軸、未來重要節點、條款提醒、需求、結論）。
- 保費配置依類別歸組，對照表在 `clients/report.js` 的 `PREMIUM_GROUPS`；理財類別在 `shared/kb.js` 的 `KB_WEALTH_CATS`。**新增類別時記得兩處一起加**，否則會落到「複合／未拆分」。

## 三、產險管理（`policies/`）
- 版型與人壽管理統一：標題「客戶保單管理」，右上分頁「＋ 新增客戶」「📁 保單彙總」「⚙ 保單條款」。
- **保單彙總**：個人保險與汽／機車保險統一收納，比照人壽「客戶清單」分「全部／同住址／群組」。
  - 全部：「保單明細」表，可切換車險／個人險；欄位為車牌號（個人險為投保商品）、被保人、同住／群組。
  - 同住址：依被保人地址歸組（兩位以上被保人才算），可「設為群組」。
  - 群組：存在每張保單的 `groups` 陣列；在保單詳細資料上方可加入或移出群組，也能改名、解散。
- **保單條款**：列出車險代號（強制險、車損險、責任險、附加條款）與個人保險商品計畫，目前為唯讀。
- 建檔流程（汽／機車）：類別 → 車牌與車種 → 投保內容明細 → 保費 → 保期 → 被保人詳細資料（含姓名）→ 車籍 → 確認。編輯時跳過類別頁。
- **保單歸戶**：新增時輸入已建過檔的車牌，自動帶入原本那筆資料並直接跳到投保內容明細（例如先建強制險、之後補任意險）。
- 投保內容明細：點「21 強制險」卡片＝有投保強制險，右邊出現強制險保單號碼欄；任一任意險項目被選取時，「任意險」標題右邊出現任意險保單號碼欄。
- 保費：強制險、任意險各一張卡（沒投保的反灰），下方自動加總；存 `compulsory_premium`、`voluntary_premium`、`total_premium`。舊資料的「3678+658」寫法在編輯時會自動拆回兩格。
- 詳細資料的「投保內容」含 21 強制險（20萬/300萬）；舊名稱項目（三責、乘客傷害險、駕傷（實支）等）自動對回代號，與新資料重複的舊項目不再重複顯示。
- 汽／機車強制險、任意險保期分開，可勾「同強制險」。
- 投保內容明細：代號卡片格（桌機一排 6 張，平板 4／3 張，手機 2 張），分「強制險」「車損險」「責任險」「附加條款」四區（21 強制險卡片依險種選擇自動亮起，不能點）；點卡片選取，需要保額的項目在下方展開設定。
- 車損險（0G、0J、0K、0L、0X、18）保額選填；附加條款（KP02、KP05、KP12、KP17）不需保額。
- 責任險：27／31／32 連動、30／51A／83 下拉、3B 三項綁定、50B → 駕傷實支、59 → 駕傷（機車單一事故）。

## 五、財經日報與 LINE 推播

- **截圖**：`.github/workflows/daily-snapshot.yml` 週一到週五 08:05／08:20／08:35／08:50 執行 `tools/snapshot.mjs`，把 `market/` 拍成圖放到 `daily-report` 分支（只留 7 天）；當天已拍好就跳過。Runner 固定 `ubuntu-24.04`（26.04 的 Playwright 不支援）。
- **推播**：09:00 由 `expiry-reminders` 發送日報與保單到期提醒，週六、日不發。
- **推播管道**（`line_links.report_channel`）：dkyp2377 → Discord；tpbu → LINE；Minnie → 停發日報。保單到期提醒一律走 LINE，每人可選提前 30／60／90 天（`line_links.remind_days`），到期前 10 天另發一次「最後提醒」（`due_reminders_final`，`reminder_log.kind = '10d'`）。
- **LINE 官方帳號**：只有傳「綁定」（或說明／HELP）才回罐頭訊息；圖文選單由 `setup-richmenu` 上傳（body 可帶 `{"ref": commit SHA}` 避開快取）。

### Edge Functions

| 名稱 | 用途 |
|---|---|
| `expiry-reminders` | 每日日報＋保單到期提醒 |
| `line-webhook` | LINE 官方帳號收訊（綁定等） |

| `trigger-snapshot` | 主動觸發截圖 workflow |

| `jarvis-line`、`arthur-hub`、`arthur-discord` | A.R.T.H.U.R.（`eastonesd/arthur`）使用 |

## 七、維護規則

- 修改前先 `git pull`；commit 作者用 `eastonesd` / `eastone.sd@gmail.com`；直接推 `main`，不走手動合併 PR。
- 網頁不可放 service_role／secret key。LINE、GitHub、Anthropic 金鑰與 Discord webhook 一律由管理員在 Supabase 後台設定，不在對話或程式碼中出現。
- 所有 HTML 內的 CSS／JS 都帶版本號 `?v=日期-序號`，改檔後要一起遞增，避免瀏覽器吃舊檔。

## 八、理賠／契變文件

`index.html` 內的 `companies`（理賠）與 `endorseCompanies`（契變）陣列決定畫面上的公司與順序：`name` 是顯示名稱，`file` 是檔名；官網提供線上表單的公司改用 `type:"link", link:"網址"`（例：安聯、元大）。

- 理賠 PDF 放 `pdfs/`，檔名用英文（例 `cathay.pdf`、`fubon.pdf`、`fuboncar.pdf`）。
- 契變 PDF 放 `pdfs-endorse/`，檔名用中文（例 `國泰人壽契變書.pdf`）。
- 下載後的檔名會自動變成「公司名稱_…申請書.pdf」。

網站含 `manifest.json`，iOS 可用 Safari「加入主畫面」、Windows 可用 Edge／Chrome「安裝此網站」，像 App 一樣開啟。
